# Internationalization (i18n) Documentation

## Overview

This application uses **i18next** with React for comprehensive internationalization support. The implementation includes:

- **4 Supported Languages**: English, Spanish, French, German
- **Locale-Aware Formatting**: Dates, times, numbers, and currency
- **RTL Support**: Ready for Arabic, Hebrew, Persian, and Urdu languages
- **Browser Language Detection**: Automatic detection with localStorage persistence
- **Accessible Language Switcher**: Full keyboard and screen reader support

## Core Modules

### 1. i18n.js

Initializes i18next with all language resources and RTL support:

```javascript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';
import { SUPPORTED_LANGUAGES } from './i18n';

export const SUPPORTED_LANGUAGES = [
  { code: 'en', label: 'English', name: 'English' },
  { code: 'es', label: 'Español', name: 'Spanish' },
  { code: 'fr', label: 'Français', name: 'French' },
  { code: 'de', label: 'Deutsch', name: 'German' },
];
```

**Key Features**:
- Browser language detection via `i18next-browser-languagedetector`
- localStorage persistence for user preference
- Automatic document attribute updates (`lang`, `dir`)
- RTL class management for CSS styling

### 2. LanguageContext.jsx

Provides global language state and utilities:

```javascript
import { useLanguage } from './context/LanguageContext';

function MyComponent() {
  const {
    currentLanguage,      // Current language code (e.g., 'en')
    isRTL,               // Boolean: is RTL language?
    direction,           // 'rtl' or 'ltr'
    changeLanguage,      // Change language function
    getLanguageInfo,     // Get metadata for a language
    getSupportedLanguages, // Get all supported languages
    detectBrowserLanguage, // Detect user's browser language
  } = useLanguage();
}
```

### 3. i18nFormatters.js

Provides locale-aware formatting utilities:

```javascript
import {
  formatLocalDate,
  formatLocalDateShort,
  formatLocalTime,
  formatLocalCurrency,
  formatLocalNumber,
  formatLocalPercentage,
  isRTLLanguage,
  getLanguageDirection,

// Usage examples
const formattedDate = formatLocalDate('2024-01-15', 'en'); // Jan 15, 2024
const price = formatLocalCurrency(1234.56, 'USD', 'es');   // $1.234,56 (Spanish)
const distance = formatLocalDistance('2024-01-01', 'en');  // "15 days ago"
```

## Usage Examples

### Basic Translation

In any React component:

```javascript
import { useTranslation } from 'react-i18next';

function Marketplace() {
  const { t } = useTranslation();
  
  return (
    <h1>{t('marketplace.title')}</h1>
    <p>{t('marketplace.availableAssets')}</p>
  );
}
```

### Language Switching

```javascript
import { useLanguage } from './context/LanguageContext';

function LanguagePicker() {
  const { changeLanguage, getSupportedLanguages } = useLanguage();
  
  return (
    <div>
      {getSupportedLanguages().map((lang) => (
        <button
          key={lang.code}
          onClick={() => changeLanguage(lang.code)}
        >
          {lang.name}
        </button>
      ))}
    </div>
  );
}
```

### Formatting Dates and Numbers

```javascript
import { formatLocalDate, formatLocalCurrency } from './utils/i18nFormatters';
import { useLanguage } from './context/LanguageContext';

function TransactionItem({ date, amount }) {
  const { currentLanguage } = useLanguage();
  
  return (
    <div>
      <span>{formatLocalDate(date, currentLanguage)}</span>
      <span>{formatLocalCurrency(amount, 'USD', currentLanguage)}</span>
    </div>
  );
}
```

### RTL Support

The application automatically applies RTL styling when an RTL language is active:

```javascript
import { useLanguage } from './context/LanguageContext';

function MyComponent() {
  const { isRTL, direction } = useLanguage();
  
  return (
    <div style={{ direction }}>
      {/* Content automatically flows RTL if needed */}
    </div>
  );
}
```

## Adding a New Language

Follow these steps to add a new language (e.g., Arabic):

### 1. Create Translation File

Create `frontend/src/locales/ar.json`:

```json
{
  "nav": {
    "marketplace": "السوق",
    "portfolio": "المحفظة",
    "admin": "إدارة",
    "history": "السجل"
  },
  "wallet": {
    "connect": "توصيل محفظة",
    "connecting": "جاري التوصيل…",
    "disconnect": "قطع الاتصال",
    "connected": "متصل"
  },
  ...
}
```

### 2. Update i18n.js

```javascript
import ar from './locales/ar.json';

export const SUPPORTED_LANGUAGES = [
  { code: 'en', label: 'English', name: 'English' },
  { code: 'es', label: 'Español', name: 'Spanish' },
  { code: 'fr', label: 'Français', name: 'French' },
  { code: 'de', label: 'Deutsch', name: 'German' },
  { code: 'ar', label: 'العربية', name: 'Arabic' },  // ← Add this
];

i18n.init({
  resources: {
    en: { translation: en },
    es: { translation: es },
    fr: { translation: fr },
    de: { translation: de },
    ar: { translation: ar },  // ← Add this
  },
  // ... rest of config
});
```

### 3. Update date-fns Locale (if needed)

The i18nFormatters.js already includes:

```javascript
const LOCALE_MAP = {
  en: enUS,
  es: es,
  fr: fr,
  de: de,
  ar: ar,  // ← Add if date-fns supports it
};
```

### 4. Update RTL Languages (if applicable)

In `i18nFormatters.js`, the `RTL_LANGUAGES` set already includes Arabic:

```javascript
export const RTL_LANGUAGES = new Set(['ar', 'he', 'fa', 'ur']);
// Arabic is already here, so RTL support works automatically!
```

### 5. Test

- Change language in the UI
- Verify translations appear correctly
- For RTL languages: check that page direction changes to RTL
- Test date/number formatting for the locale

## Best Practices

### 1. Key Naming

Use hierarchical, descriptive keys:

```json
{
  "page.section.element": "Translation"
}
```

✅ Good:
```javascript
t('marketplace.shareBalance')
t('portfolio.noHoldings')
t('common.loading')
```

❌ Avoid:
```javascript
t('text1')
t('msg')
t('btn')
```

### 2. Interpolation

Use named variables for dynamic content:

```json
{
  "welcome": "Welcome, {{name}}!"
}
```

```javascript
t('welcome', { name: 'John' }) // "Welcome, John!"
```

### 3. Pluralization

Use i18next pluralization features:

```json
{
  "itemCount": "You have {{count}} item",
  "itemCount_plural": "You have {{count}} items"
}
```

### 4. Context-Aware Formatting

Always use the appropriate formatter for the context:

```javascript
// Transaction date - show full date and time
formatLocalDateLong(txDate, lang)

// Portfolio summary - show short date only
formatLocalDateShort(txDate, lang)

// Recent transaction - show relative time
formatLocalDistance(txDate, lang) // "2 hours ago"

// Currency amount
formatLocalCurrency(amount, 'USD', lang)
```

### 5. RTL Considerations

When building RTL-aware components:

```javascript
// ❌ Avoid inline styles that break RTL
<div style={{ paddingLeft: '20px' }}>Content</div>

// ✅ Use CSS variables or classes
.component {
  padding-left: var(--spacing-md);
  // CSS RTL utilities will handle the flip
}
```

    expect(formatLocalCurrency(1234.56, 'USD', 'en')).toBe('$1,234.56');

});

## Troubleshooting

### Translation Not Appearing

1. Check that the key exists in all language JSON files
2. Verify the key path matches exactly (case-sensitive)
3. Ensure i18n is initialized before component render
4. Check browser console for i18next warnings

### RTL Not Activating

1. Confirm the language is in `RTL_LANGUAGES` set
2. Check that document `dir` attribute is set: `<html dir="rtl">`
3. Verify `rtl` class is on `<html>` or `<body>`
4. Check CSS is targeting the correct selector

### Browser Language Not Detected

1. Verify `i18next-browser-languagedetector` is installed
2. Check that browser language preference is set
3. localStorage might override browser detection - check localStorage
4. Device language preference should match a supported language code

## Performance Considerations

- Translations are loaded once at app startup
- No runtime language switching performance impact
- Date-fns locales are tree-shaken by the bundler
- localStorage caching prevents repeated lookups

## Accessibility

- All language names use full text in tooltips (not just codes)
- Language selector buttons have proper ARIA labels
- Document `lang` attribute is set for screen readers
- `dir` attribute ensures proper text direction
- All translations should be reviewed for clarity and correctness
